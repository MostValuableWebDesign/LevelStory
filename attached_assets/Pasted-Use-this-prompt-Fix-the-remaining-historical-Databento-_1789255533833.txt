1. Make import cancellation and recovery genuinely resumable

Relevant files:

- `artifacts/api-server/src/lib/futures/multi-contract-replay.ts`
- `artifacts/api-server/src/lib/futures/historical-index-store.ts`
- `artifacts/api-server/src/routes/historical-data-upload.ts`
- `artifacts/api-server/src/lib/futures/historical-import-job-store.ts`

Current problem:

- `buildMultiContractIndex()` catches every error and calls `stagedStore.abortAtomic()`.
- `abortAtomic()` closes and deletes the staging SQLite database.
- The import checkpoint is stored inside that staging database.
- Therefore, cancellation or a recoverable interruption deletes the checkpoint it needs for resumption.
- `preserveAtomic()` exists but is not used for recoverable cancellation/interruption.
- Checkpoints are written only after a complete physical source file finishes. With one five-year file, an interruption can cause the entire file to be parsed again.

Required behavior:

- Distinguish recoverable interruption/cancellation from unrecoverable corruption, incompatibility, or fingerprint mismatch.
- On user cancellation, shutdown, lease interruption, or another recoverable interruption:
  - finish or roll back the current SQLite transaction safely;
  - persist the latest verified checkpoint;
  - close the staging database without deleting it;
  - retain `stagingIndexPath` and checkpoint metadata in the durable import-job record;
  - mark the job as `paused` or `cancelled_resumable`, not permanently terminal;
  - expose an explicit Resume action/route.
- Use `preserveAtomic()` or equivalent safe behavior for recoverable interruptions.
- Use `abortAtomic()` only when the staging index is invalid and must be discarded.
- A source fingerprint mismatch must never reuse an incompatible checkpoint.
- Never modify or delete the previous committed historical library while a replacement is incomplete.

Checkpoint granularity:

- Do not checkpoint only at the end of the five-year physical file.
- Create verified restart boundaries during streaming, preferably by completed contract/trading-date partition.
- Persist sufficient state to skip already completed partitions after restart.
- Do not mark a trading-date partition complete until every row belonging to that partition and its required 5-minute aggregation has been safely committed.
- If compressed-stream byte offsets cannot be safely resumed, restart the source stream but skip already committed, verified partitions without rewriting/reaggregating them.
- Progress totals must continue from the checkpoint rather than reset or double-count.
- Repeated resume operations must be idempotent.

Add tests proving:

- Cancellation preserves the staging SQLite file and its checkpoint.
- A cancelled/resumable job can be resumed.
- Resume skips completed partitions.
- Resume does not duplicate one-minute or five-minute candles.
