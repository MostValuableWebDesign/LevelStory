- requestFingerprint
- validationConfigFingerprint

Before approve, publish, or activate, require:

- validation run status is passed
- validation version equals the current version

Existing proposals in validation_passed, approved, or candidate state must not proceed until a current validation run passes.

3. Make false-positive submission atomic

Move all false-positive validation into recordVisualValidationReview before mutating:

- stored.reviews
- reviewHistory
- persistent teaching storage

Require:

- teaching payload exists
- judgment is false_positive_trade
- validation.valid is true
- exact machine trade exists
- strategy matches the machine trade
- direction matches
- entry/fill candle matches the machine trade
- entry price matches under the applicable execution policy
- reviewer explanation is present

If any check fails, make no state change.
