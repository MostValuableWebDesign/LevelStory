`file.startsWith("glbx-mdp3-")`

3. Move materialization and indexing out of the HTTP request

Current defect:

`POST /historical-data/import` waits for `importHistoricalMultiContract()` to finish before returning its `202` response. A five-year import can keep the browser request open long enough to exceed platform or proxy timeouts.

Required workflow:

B. Browser submits the uploaded object references to:

`POST /historical-data/import`

C. The endpoint must:

- Validate the request.
- Create an import job.
- Return HTTP 202 immediately.
- Return:
  - `jobId`

- Materialize the requested objects.
- Fingerprint them.
- Validate filenames, compression, schema, symbols, and rows.
- Build the staged SQLite index.
- Atomically publish the staged database only after successful validation.
- Keep the previously ready database available while a replacement is built.
- Mark the job completed or failed.

4. Bound importer memory use

Current remaining issue:

`importHistoricalCsv()` still accumulates every candle from a source file in:

- a candle array
- a timestamp map
- aggregated arrays

The worker then returns the complete imported object to the main thread. Large files can therefore be duplicated across worker and main-process memory.

Required behavior:

- Keep `.csv.zst` decompression streaming.
- Parse and validate incrementally.
- Write validated one-minute candles to the staged SQLite database in bounded batches, such as 5,000–20,000 rows.
- Generate required five-minute candles incrementally or in a bounded per-date/per-session pass.
- Do not send complete candle arrays from a worker to the parent process.
- Worker messages should contain bounded progress events, summaries, and errors.
- Memory use should be governed by the batch size and current trading-date aggregation—not total file size.
- Preserve:
  - duplicate detection
  - conflicting-timestamp rejection
  - OHLCV validation
  - source row numbers
  - session coverage
  - file fingerprints
  - source summaries
- Support multiple fragments for the same contract.
- Identical overlapping rows may be deduplicated.
- Conflicting overlapping rows must fail closed with the contract, timestamp, and source files identified.
- A failed staged import must not damage the currently ready index.
- Close SQLite connections and worker resources after replacement, failure, or cancellation.
